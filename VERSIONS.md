# VERSIONS

Each change of the crate version and the public API changes it carries
(AGENTS.md, "Versions and tags"). Internal changes are not listed, and there
is no entry without a version change. Entries are appended, oldest first,
and never edited.

## 0.1.0 — 2026-10-13 (`21938c4`, tag `v0.1.0`)

Initial release, and every change up to `3da1e1f`. Recorded retroactively on
2026-10-16; the tag was added on 2026-10-16.

## 0.1.1 — 2026-10-16 (tag `v0.1.1`)

cpal on Android (`docs/design/20261016_01_CPAL_FEATURE_PLAN.md`). The commit
is the one tagged `v0.1.1`: the entry is written in that commit, which
cannot name its own hash.

- Added the `cpal` feature: cpal 0.18 as an optional Android dependency,
  re-exported as `libmobile::android::cpal`. It turns on `ndk`'s `audio`
  and `api-level-26` features.

## 0.2.0 — 2026-10-22 (tag `v0.2.0`)

Runtime permissions (`docs/design/20261022_01_RUNTIME_PERMISSIONS_PLAN.md`)
and audio capture with input presets
(`docs/design/20261022_02_AUDIO_CAPTURE_PLAN.md`). The commit is the one
tagged `v0.2.0`: the entry is written in that commit, which cannot name its
own hash.

- **Breaking:** the `cpal` feature also turns on `ndk`'s `api-level-28`
  feature, for AAudio input presets, so an app built with it needs Android 9
  (API 28). Projects generated by `libmobile::gradle` already target API 29.
- Added runtime permission requests:
  `android::request_permissions(&AndroidApp, &[&str]) -> PermissionRequest`,
  `android::permission_granted` and `android::should_show_rationale`; the
  types `PermissionRequest` (`id()`) and `PermissionsOutcome { request,
  permissions }` (`#[non_exhaustive]`, `granted()`); and
  `MobileEvent::Permissions`. Requests are made one at a time, in order,
  and each gets one answer carrying its id.
- Added to the Kotlin side: `MobileActivityPlugin.onRequestPermissionsResult`
  (default `false`), dispatched by `MobileNativeActivity`, and the core
  plugin `bridge.PermissionPlugin`, present in every generated project.
- Added under the `cpal` feature: `android::CaptureStream` (`open` with an
  optional input preset and a callback, `format`, `preset`, `set_preset`,
  `start`, `stop`), and the platform-free `InputPreset` (`to_raw`,
  `from_raw`), `CaptureFormat` and `CaptureError`, in the new module
  `audio_capture`.

## 0.2.1 — 2026-10-22 (tag `v0.2.1`)

The secure store (`docs/design/20261022_03_SECURE_STORE_PLAN.md`) and the
key store (libmorph `docs/design/20261022_06_KEY_STORE_PLAN.md`). All
additions. The commit is the one tagged `v0.2.1`.

- **Secure store** (core):
  - `android::secure_store::{get, put, put_with, delete,
    security_level}` and `android::SecureStore`: named blobs sealed with
    AES-256-GCM under a non-exportable Android Keystore key (StrongBox when
    present), in no-backup storage;
  - the platform-free `SecureStoreError` (`#[non_exhaustive]`: `InvalidName`,
    `TooLarge`, `Keystore`, `DeviceLocked`, `Io`, `Corrupt`,
    `Platform`), `SecurityLevel` and `PutOptions` (`unlocked_only`);
  - no `AndroidApp` argument: it uses the Application from `ndk-context`.
- **Key store** (core):
  - the module `key_store`: `generate`, `public`, `with_key` and
    `delete` over a `Vault` (`Vault::named(namespace)`);
  - the `SecretKey` trait for adapters, `SealToken`, `KeyStoreError`
    (`#[non_exhaustive]`), and `FLAG_DEVICE_UNLOCK_REQUIRED` and
    `FLAG_APP_UNLOCK_REQUIRED` (reserved, refused);
  - the same engine file as libdevice's.
- **Features:** `secure-store-no-strongbox` (keeps the Keystore keys in the
  TEE) and `test-vault` (`Vault::memory()`, for tests only).
- **Kotlin:** the core plugin `store.SecureStorePlugin` is in every
  generated project, and `GeneratedPlugins.SECURE_STORE_STRONGBOX` is
  generated.
- **Dependencies:** `zeroize` 1.8 (with `derive`) is new, and so, on
  Android, is `ndk-context` 0.1, which shares android-activity's copy.

## 0.2.2 — 2026-10-22 (tag `v0.2.2`)

URL schemes (`docs/design/20261022_05_URL_SCHEMES_PLAN.md`). All
additions. The commit is the one tagged `v0.2.2`.

- `gradle::Project::url_scheme(scheme)`: the generated manifest's activity
  gets a `VIEW`/`DEFAULT`/`BROWSABLE` intent filter for the scheme, with no
  App Links. Links reach the app as `MobileEvent::Intent`, as other
  intents do.
- `codegen::url_scheme_filters(&[String]) -> String`, the filters' XML.
- `intent::redact_url(&str) -> String`: a URL cut after its path. The
  intent log line now uses it and leaves out extra values. That is not API.

the battery exemption (`docs/design/20261023_02_BATTERY_EXEMPTION_PLAN.md`),

## 0.3.0 — 2026-10-28 (tag `v0.3.0`)

The in-process camera, single-frame capture and opening the app's Settings
page (`docs/design/20261028_01_CAMERA_CAPTURE_AND_QR_PLAN.md` and its
amendment of 2026-10-28 14:46 EDT). `MobileEvent` is `#[non_exhaustive]`.

- **Breaking: feature `camera` renamed `camera-intent`** (the system camera
  app hand-off, `ACTION_IMAGE_CAPTURE`). `libmobile::camera::CaptureOutcome`
  moves to `libmobile::camera_intent::CaptureOutcome`, and
  `android::camera::capture_photo` to `android::camera_intent::capture_photo`
  (`android::capture_photo` is unchanged). Its Kotlin plugin is now
  `cameraintent.CameraIntentPlugin`. Its manifest contribution is unchanged.
- **Breaking: feature `camera` is now the in-process NDK camera** (`ACamera*`,
  `AImageReader`, no Jetpack). It adds `CAMERA` and optional
  `android.hardware.camera`, `camera.autofocus` and `camera.any`
  `uses-feature`s to the manifest, and links `libcamera2ndk`. CAMERA is
  asked for on the first camera call, never at launch.
  `libmobile::camera::{Facing, SessionId, CaptureId, CameraError,
  CameraEvent, ZoomSource, PreviewOptions, PreviewFrame}`;
  `android::camera::{start_preview, stop, latest_preview, zoom_range, zoom,
  set_zoom, zoom_by}`; `MobileEvent::Camera`. A refusal fails with
  `CameraError::PermissionDenied { settings_only }`. With `camera-intent`
  also on, `capture_photo` asks for CAMERA first.
- **Feature `camera-capture`:** `capture_frame` and `cancel_capture`, with
  `CaptureOptions`, `FrameFormat` (`Gray8`, `Rgba8`, `Jpeg`), `Resolution`
  (`Preview`, `Max`, `AtMost`) and `Frame`; `CameraEvent::Frame`.
- **Core:** `android::open_app_settings(&AndroidApp)`, which opens this app's
  page in Settings; errors are `OpenLinkError`.
